A palette you can trust

1. Start with the brand color

Paste six-digit or shorthand hex with or without #. Alpha colors are rejected. Secondary, Grey and status colors are optional.

2. Review the exact output

Choose six tints or ten tones. Preview uses the same calculation as generation. Level 500 is your original color; edited tones are included everywhere.

3. Review asset changes

Generate opens a create/update summary. Same-name assets made by another tool need an explicit update choice. A new collection name avoids variable conflicts; style names must also be unique.

4. Understand themes

Palette variables are primitives in one Value mode. Darker tones alone do not change a theme. Semantic roles such as Text/Primary point to different palette tones in Light and Dark.

5. Check real pairs

A color itself does not pass WCAG. A specific foreground/background pair does. Check body text, buttons, borders and status messages in their actual context; use labels/icons as well as hue.

6. Keep documentation consistent

Guides and token frames are static snapshots. Regeneration replaces this plugin’s previous snapshot on the current page at its existing position. Manual variable edits do not change snapshot colors or labels.

7. Export a known revision

Tokens describe the last exported or generated snapshot. Editing the draft marks them as previous output. Downloading or switching formats does not change your document.

Generation journals asset updates and attempts rollback on errors. Recovery failures are reported explicitly. Gradients use approximate CSS; structured exports retain raw Figma geometry.
